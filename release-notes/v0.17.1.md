**Fix, from your problem report: "connection reset by peer, error 104" when streaming from a relay's HackRF**

The relay had been updated to 0.2.0 but its window was still set to "RTL-SDR 0", and only the HackRF was plugged in. Every stream asked for the absent RTL-SDR, and the relay hung up.

- **The toolkit now picks the device itself.** It uses the device set in the relay's window if it's plugged in; otherwise it uses one the relay actually has (here the HackRF). Nothing needs changing on the relay's PC.
- **A relay with several devices** (an RTL-SDR and a HackRF, say) gets a **Device** list in the relay button's menu. Your pick is remembered for that relay.
- **A refused stream says why:** the relay's own reason ("Couldn't open the RTL-SDR...") is shown instead of "Errno 104".

Tested against a stand-in relay set up like yours (window on RTL-SDR 0, only a HackRF listed); not yet with the real HackRF.
